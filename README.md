# 📺 MyTube

> Собственный видеохостинг в духе YouTube — микросервисы, HLS-стриминг, очереди задач и аутентификация через Google.

MyTube — это полноценная платформа для загрузки и просмотра видео, собранная с нуля. Вы загружаете ролик — сервис сам нарезает его на адаптивные HLS-потоки 720p/1080p в фоновом режиме, генерирует превью и отдаёт готовое видео через браузерный плеер. Всё работает в одном `docker compose`, а разворачивается одной командой.

| 📈 **Статистика** | Просмотры, лайки, дизлайки, репосты — всё учитывается |
| 💬 **Комментарии** | Комментирование с лайками/дизлайками и «живой» оптимистичный UI |
| ⏯️ **Продолжить просмотр** | Позиция запоминается автоматически: возвращайтесь к ролику и продолжайте с того же места |

| 🌗 **Тёмная тема** | Автоматически подстраивается под системную тему устройства |

## 🏗️ Архитектура

MyTube построен по принципу микросервисов: каждый сервис живёт в собственном контейнере, имеет свою базу данных и отвечает только за свою зону ответственности.

```
                             ┌──────────────────────────────┐
        http://localhost     │            GATEWAY           │
        ───────────────────► │        Nginx (порт 80)       │
                             │  статика React + reverse proxy│
                             └───────┬──────┬──────┬────────┘
                                     │      │      │
                  /auth              │      │      │ /video, /comments
                                     ▼      │      ▼
                          ┌────────────────┐│ ┌──────────────────────┐
                          │  auth_service  ││ │    video_service     │
                          │  FastAPI       ││ │    FastAPI           │
                          │  (порт 8001)   ││ │    (порт 8002)       │
                          └───────┬────────┘│ └─────┬───────┬────────┘
                                  │          │      │       │
                          ┌───────▼──────┐   │  ┌────▼───┐ ┌▼────────────┐
                          │ PostgreSQL   │   │  │  Redis │ │ PostgreSQL  │
                          │ (пользователи)│  │  │(backend│ │ (видео)     │
                          └──────────────┘   │  │ Celery)│ └─────────────┘
                                             │  └────────┘
                                             │  ┌─────────────────────────┐
                                             │  │     celery_worker       │
                                             │  │  FFmpeg → HLS + MinIO   │
                                             │  └─────────────┬───────────┘
                                             │                │
                                             │       ┌────────▼────────┐
                                             │       │ RabbitMQ (брокер)│
                                             │       └─────────────────┘
                                             │                │
                                             └────────────────▼
                                                       ┌────────────────┐
                                                       │  MinIO (S3)    │
                                                       │  /videos/…     │
                                                       └────────────────┘
```

### Поток загрузки видео

1. Авторизованный пользователь загружает файл → `video_service` создаёт запись со статусом `pending` и сохраняет `.mp4` во временную папку.
2. В очередь RabbitMQ уходит задача → **Celery worker** подхватывает файл.
3. FFmpeg извлекает кадр для превью, проверяет наличие аудио и в **один проход** нарезает ролик на два качества (720p / 1080p), формируя `master.m3u8`.
4. Все `.ts`-сегменты, плейлисты и thumbnail заливаются в **MinIO** (S3-совместимое хранилище).
5. Статус видео меняется на `ready`, в базу записывается длительность.
6. Плеер забирает `master.m3u8` и стримит видео напрямую из MinIO.

## 🧰 Технологический стек

### Backend
| Сервис | Технологии |
|---|---|
| `auth_service` | Python 3.11, FastAPI, fastapi-users, SQLAlchemy 2.0 (async), asyncpg, httpx-oauth, PyJWT |
| `video_service` | Python 3.11, FastAPI, SQLAlchemy 2.0 (async), asyncpg |
| `celery_worker` | Celery 5, FFmpeg (static build), boto3 |

### Frontend
React 19, Vite 8, React Router 7, hls.js, Oxlint — единый SPA в стилистике YouTube.

### Инфраструктура (Docker)
PostgreSQL 15, RabbitMQ 3 (management), Redis 7, MinIO, Nginx.

## 🚀 Быстрый старт

### Требования
- Docker + Docker Compose
- (опционально) настроенные Google OAuth credentials для входа через Google

### Запуск

```bash
docker compose up --build
```

Готово! Открывайте http://localhost:

| Что | Адрес | Логин / пароль |
|---|---|---|
| 🖥️ MyTube (веб-интерфейс) | http://localhost | — |
| 📚 Swagger Auth Service | http://localhost:8001/docs | — |
| 📚 Swagger Video Service | http://localhost:8002/docs | — |
| 🐇 RabbitMQ (админка) | http://localhost:15672 | `guest` / `guest` |
| 🗄️ MinIO (консоль) | http://localhost:9001 | `minioadmin` / `minioadminpassword` |

### Настройка Google OAuth (опционально)

В `docker-compose.yaml` для сервиса `auth_service` замените `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` на свои значения из Google Cloud Console. Без этого вход через Google будет недоступен — останется обычная регистрация по email.

> ⚠️ В `docker-compose.yaml` лежат dev-значения секретов. Для продакшена обязательно вынесите их в переменные окружения или `.env` и не коммитьте реальные ключи.

## 🔌 Основные API-эндпоинты

### Auth Service (`/auth`)
| Метод | Путь | Описание |
|---|---|---|
| POST | `/auth/register` | Регистрация |
| POST | `/auth/login` | Вход (Bearer JWT) |
| POST | `/auth/refresh` | Обменять refresh-токен на новый access-токен |
| GET | `/auth/authorize` | URL авторизации Google |
| GET | `/auth/callback` | Callback Google OAuth |
| GET | `/users/me` | Текущий пользователь |

### Video Service (`/video`, `/comments`)
| Метод | Путь | Описание |
|---|---|---|
| POST | `/video/upload` | Загрузка видео (multipart) |
| GET | `/video/feed?page=&size=` | Лента готовых видео (пагинация) |
| GET | `/video/storage/{id}` | Карточка видео + счётчик просмотров |
| POST | `/video/{id}?activity_type=` | Лайк / дизлайк / репост |
| GET/POST | `/video/{id}/timecode` | Получить / сохранить позицию просмотра |
| GET | `/comments/videos/{id}` | Комментарии к видео |
| POST | `/comments/videos/{id}` | Добавить комментарий |
| POST | `/comments/{id}?activity=` | Лайк / дизлайк комментария |

Статусы видео: `pending` → `processing` → `ready` / `failed`. В ленту попадают только `ready`-ролики.

## 🧠 Как это устроено внутри (интересные детали)

- **Адаптивное качество без рассинхрона.** FFmpeg получает один `filter_complex` с `split=2` — обе дорожки кодируются из одного потока, поэтому видео и звук не разъезжаются (подробнее в `video_service/app/utils/tasks.py`).
- **Мягкое «продолжить просмотр».** Раз в 15 секунд плеер отправляет текущий таймкод на сервер, а перед закрытием вкладки — `navigator.sendBeacon`. При следующем визите ролик стартует с сохранённой секунды.
- **Оптимистичный UI.** Лайки и дизлайки на комментариях обновляются мгновенно, а при ошибке запроса откатываются обратно — никаких «скучных» ожиданий.
- **Отдельные базы данных.** У auth и video сервисов — собственные PostgreSQL. Это классический микросервисный подход: сервисы не зависят от внутренних схем друг друга.
- **Статический FFmpeg.** Образ воркера скачивает официальный static-билд, что избавляет от танцев с системными пакетами и ускоряет сборку контейнера.
